# SPEC-INFRA-001: Nextra 4.x Ontology Education Site Infrastructure

## Overview

This SPEC defines the complete infrastructure setup for the Ontology Fundamentals Learning Platform (ontology-class), a Nextra 4.x documentation site teaching ontology concepts to Korean beginners. This SPEC covers project initialization, App Router configuration, content directory scaffolding, skeleton MDX files, custom React components, and styling. Content generation is explicitly excluded and handled by separate SPEC-CONTENT-P[N] SPECs.

## Assumptions

### A-001: Nextra 4.x App Router Pattern

Nextra 4.x exclusively uses the Next.js App Router. The content directory (`content/`) holds MDX files organized by `_meta.js` navigation metadata. The catch-all route `app/[[...mdxPath]]/page.tsx` dynamically imports and renders MDX content using `importPage` from `nextra/pages` and `generateStaticParamsFor`.

### A-002: Content Directory Convention

Nextra 4.x uses the `content/` directory (not `pages/`) to organize MDX files without requiring the `page.mdx` filename convention. Each directory level has a `_meta.js` file controlling sidebar navigation order and display labels.

### A-003: Component Integration via mdx-components

Nextra 4.x requires a root-level `mdx-components.tsx` file exporting `useMDXComponents` that merges theme components with custom components. This is the mechanism for making custom components globally available in MDX content.

### A-004: Mermaid Client-Side Rendering

Mermaid diagrams render client-side. The `MermaidDiagram` component must use `'use client'` directive, dynamic import with `{ ssr: false }`, and handle loading states. Mermaid node labels must not contain apostrophes. The `+` operator is forbidden in `stateDiagram-v2` transitions.

### A-005: No JSX Imports in MDX

Per project content quality standards, MDX files must NOT use JSX `import` statements. Custom components are made available globally via `mdx-components.tsx`. Interactive elements like callouts use blockquote `>` syntax instead of imported components.

### A-006: Korean Font Support

The site requires proper Korean (Hangul) font rendering. Noto Sans KR or equivalent Korean-optimized font must be configured via CSS or Next.js font optimization, supporting all Hangul characters and Unicode ranges.

### A-007: Greenfield Project

This is a new project with no existing code. There is no legacy code to preserve, no existing tests, and no database. The entire infrastructure is created from scratch.

### A-008: Skeleton MDX Content Only

This SPEC produces skeleton MDX files with proper frontmatter, Korean section headers matching the template structure, and placeholder content. Actual educational content is generated by separate SPEC-CONTENT-P[N] SPECs for each phase.

## Requirements

### R-001: Project Initialization [UBIQUITOUS]

The system shall provide a complete Nextra 4.x documentation site with Next.js 15 App Router, configured via `package.json`, `next.config.mjs`, `tsconfig.json`, and `mdx-components.tsx`.

**Sub-requirements:**

- R-001.1: `package.json` shall declare all production and development dependencies with correct version ranges.
- R-001.2: `next.config.mjs` shall configure Nextra using the `nextra()` wrapper function imported from `'nextra'`.
- R-001.3: `tsconfig.json` shall enable strict mode, target ES2020+, configure JSX for React, and define path aliases (`@/*` mapping to project root).
- R-001.4: `mdx-components.tsx` shall export `useMDXComponents` merging `nextra-theme-docs` theme components with custom project components.

### R-002: App Router Setup [UBIQUITOUS]

The system shall provide a functional App Router with root layout, home page, and catch-all MDX route.

**Sub-requirements:**

- R-002.1: `app/layout.tsx` shall import `Layout`, `Navbar`, `Footer` from `nextra-theme-docs`, import `Head` from `nextra/components`, import `getPageMap` from `nextra/page-map`, import `nextra-theme-docs/style.css`, set `<html lang="ko">`, and pass `pageMap={await getPageMap()}` to the `Layout` component.
- R-002.2: `app/page.tsx` shall render the home page with Korean welcome content and navigation links to the 8 phases.
- R-002.3: `app/[[...mdxPath]]/page.tsx` shall use `generateStaticParamsFor('mdxPath')` and `importPage(params.mdxPath)` from `nextra/pages` to dynamically render MDX content from the `content/` directory.

### R-003: Content Directory Navigation [WHEN triggered]

**When** users navigate to any phase URL (e.g., `/phase-1/01-motivation`), **the system shall** render the corresponding MDX content from the `content/` directory with Korean text and proper sidebar navigation generated from `_meta.js` files.

**Sub-requirements:**

- R-003.1: `content/_meta.js` (root) shall define navigation entries for all 8 phases, reference section, and about section with Korean labels.
- R-003.2: Each `content/phase-{N}/_meta.js` shall define ordered entries for all MDX files within that phase, using Korean display titles.
- R-003.3: `content/reference/_meta.js` shall define entries for glossary, FAQ, misconceptions, resources, and bibliography.
- R-003.4: `content/about/_meta.js` shall define entries for the about index, curriculum, and contributors pages.

### R-007: Mermaid Diagram Rendering [STATE-DRIVEN]

**While** Mermaid diagrams are loading, **the system shall** display a loading placeholder with appropriate Korean text (e.g., "다이어그램 로딩 중...").

**Sub-requirements:**

- R-007.1: `MermaidDiagram.tsx` shall use `'use client'` directive and dynamically import Mermaid with `{ ssr: false }`.
- R-007.2: The component shall accept a `chart` prop containing Mermaid diagram definition string.
- R-007.3: The component shall render an SVG output after initialization.
- R-007.4: The component shall handle Mermaid syntax errors gracefully by displaying an error message instead of crashing.
- R-007.5: The component shall support dark mode theme switching.

### R-008: Dark Mode Mermaid Support [OPTIONAL FEATURE]

**Where** users enable dark mode, **the system shall** apply dark theme to all Mermaid diagrams using Mermaid's `theme: 'dark'` configuration and re-render diagrams on theme change.

### R-009: No JSX Imports in MDX [UNWANTED]

The system **shall NOT** use JSX component imports in MDX files. Custom components must be registered globally via `mdx-components.tsx` and used directly in MDX without import statements. Callouts and alerts shall use blockquote `>` syntax.

### R-010: Custom Components [UBIQUITOUS]

The system shall provide four custom React components:

- R-010.1: `Exercise.tsx` - Exercise template supporting `difficulty` prop (basic/challenge), collapsible solution section, Korean labels.
- R-010.2: `MermaidDiagram.tsx` - Client-side Mermaid renderer with loading state, error handling, and dark mode support (see R-007).
- R-010.3: `ConceptCard.tsx` - Visual concept summary card with title, description, icon/emoji support, and gradient background options.
- R-010.4: `CompetencyQuestion.tsx` - Self-assessment question component with question text, multiple choice options, reveal answer functionality, and Korean labels.

### R-011: Styles Setup [UBIQUITOUS]

The system shall provide global CSS with Korean font support.

**Sub-requirements:**

- R-011.1: `styles/globals.css` shall import Korean fonts (Noto Sans KR or equivalent via Google Fonts / `next/font`).
- R-011.2: CSS shall define CSS custom properties for spacing, colors, font sizes, and breakpoints.
- R-011.3: CSS shall ensure proper `font-family` fallback chain: Korean font, system sans-serif, generic sans-serif.
- R-011.4: CSS shall support both light and dark mode via Nextra's theme system.
- R-011.5: CSS shall provide responsive typography scaling for Korean text readability.

### R-012: Build Verification [UBIQUITOUS]

The system shall build successfully with zero errors.

**Sub-requirements:**

- R-012.1: `bun install` (or `npm install`) shall complete without errors.
- R-012.2: `bun run build` (or `npm run build`) shall complete with zero TypeScript errors.
- R-012.3: `bun run dev` shall start the development server and serve pages at `http://localhost:3000`.
- R-012.4: All navigation links generated from `_meta.js` files shall resolve to existing MDX content files.

### S-003: Catch-All Route Structure

```typescript
// app/[[...mdxPath]]/page.tsx
import { generateStaticParamsFor, importPage } from 'nextra/pages'
import { useMDXComponents as getMDXComponents } from '../../mdx-components'

export const generateStaticParams = generateStaticParamsFor('mdxPath')

const Wrapper = getMDXComponents().wrapper

export default async function Page(props) {
  const params = await props.params
  const result = await importPage(params.mdxPath)
  const { default: MDXContent, toc, metadata } = result
  return (
    <Wrapper toc={toc} metadata={metadata}>
      <MDXContent {...props} params={params} />
    </Wrapper>
  )
}
```

## Constraints

### C-001: Mermaid Safe Syntax

- FORBIDDEN: Apostrophes (`'`) in Mermaid node labels
- FORBIDDEN: `+` operator in `stateDiagram-v2` transitions
- ALLOWED diagram types: `graph TD`, `graph LR`, `sequenceDiagram`, `stateDiagram-v2`, `erDiagram`, `classDiagram`
- Use double-quoted labels `["text"]` for labels with special characters

### C-002: No JSX Imports in MDX

MDX files must NOT contain `import` statements for React components. All custom components are registered globally in `mdx-components.tsx`. Callouts use blockquote `>` syntax.

### C-003: Korean Content Quality Standards (per session)

These standards apply to content SPECs but skeleton files must include section headers that accommodate them:
- At least 3 "왜 필요한가?" blockquotes (placeholder sections provided)
- At least 2 "연결 포인트" callouts (placeholder sections provided)
- At least 1 "흔한 오해" section (header provided)
- Exactly 1 Mermaid big-picture diagram (placeholder provided)
- All content in Korean (tech terms in English with Korean explanation)

### C-004: File Naming Conventions

- MDX files: Numeric prefix + kebab-case (e.g., `01-motivation.mdx`)
- Components: PascalCase (e.g., `MermaidDiagram.tsx`)
- Styles: kebab-case (e.g., `globals.css`)
- Configuration: Standard names (`next.config.mjs`, `tsconfig.json`)

### C-005: TypeScript Strict Mode

- `strict: true` in tsconfig.json
- No `any` type without explicit justification
- All component props must have TypeScript interfaces
