# Implementation Plan: SPEC-ENHANCE-P4P8

## 구현 개요

Phase 4와 Phase 8의 교육 컨텐츠를 보강하여 이론-실무 간 "연결 다리"를 구축한다. 3개 파일에 대한 additive 보강을 수행한다.

---

## 마일스톤

### Primary Goal: REQ-P4P8-001 -- RDF/RDFS/OWL 3계층 비교 시연

**대상 파일**: `content/phase-4/01-rdf.mdx`

**구현 전략**:
1. 기본 사례 트리플 세트 작성 (홍길동/서울대학교 예제 확장)
   - 기존 `01-rdf.mdx`에서 사용 중인 `ex:홍길동`, `ex:서울대학교` 엔티티를 재사용하여 일관성 유지
   - 3~5개 트리플로 구성된 최소 사례

2. RDF 계층 해석 작성
   - 순수 RDF로 해석 가능한 것/불가능한 것 명시
   - "컴퓨터가 아는 것" 요약 박스

3. RDFS 계층 해석 작성
   - `rdfs:subClassOf`, `rdfs:domain`, `rdfs:range` 추가
   - 추론 결과를 구체적으로 나열

4. OWL 계층 해석 작성
   - `owl:disjointWith`, 카디널리티 제약 추가
   - 불일치 탐지 시나리오 포함

5. 비교 요약 표 및 핵심 통찰 작성

**삽입 위치**: "흔한 오해" 섹션 뒤, "실습" 섹션 전

**의존성**: 없음 (독립적, Phase 4 단독 파일)

**리스크**:
- 분량 초과 위험: 3계층 비교가 120줄을 넘길 수 있음
  - 완화: OWL 계층은 핵심 2가지(disjointWith, 카디널리티)로 한정
- RDFS/OWL 개념의 선행 학습 가정: Phase 4의 01-rdf.mdx는 RDF만 다루는 파일
  - 완화: "뒤에서 자세히 배울 내용의 맛보기"임을 명시, 간소화된 설명 사용

### Secondary Goal: REQ-P4P8-003 -- 기술 비교 연결 다리

**대상 파일**: `content/phase-8/04-technology-comparison.mdx`

**구현 전략**:
1. 기술별 적합/부적합 시나리오 표 작성
   - 4가지 기술 x 2가지 적합 + 2가지 부적합
   - 기존 "종합 비교 매트릭스"의 데이터를 행동 지침으로 전환

2. Hybrid 패턴 작성
   - 기존 "폴리글롯 아키텍처" 섹션을 참조/확장하되 중복 회피
   - 새로운 도메인(예: 전자상거래) 사례 추가

3. 판단 체크리스트 작성
   - 5~7개 Yes/No 질문으로 기술 선택 가이드
   - 기존 "종합 비교 매트릭스" 표의 내용을 의사결정 흐름으로 전환

4. 도입 신호/위험 신호 표 작성

**삽입 위치**: "종합 비교 매트릭스" 섹션 뒤, "연결 포인트" 섹션 전

**의존성**: 없음 (독립적, REQ-P4P8-001과 다른 Phase)

**리스크**:
- 기존 "폴리글롯 아키텍처" 섹션과 내용 중복 위험
  - 완화: 폴리글롯 섹션은 "사례"이고, 이 보강은 "판단 기준"으로 역할 분리

### Final Goal: REQ-P4P8-002 -- 매핑 도구 워크스루

**대상 파일**: `content/phase-8/02-mapping-problems.mdx`

**구현 전략**:
1. 두 의료 온톨로지 시나리오 설정
   - 기존 본문의 의료 온톨로지 사례(병원 A, B, 보험사)를 활용
   - 간소화된 Turtle로 각 3~5 클래스 표현

2. 4단계 매핑 워크스루 작성
   - 각 단계에서의 의사결정과 근거를 명시
   - 자동 도구의 결과와 한계를 구체적으로 보여줌

3. 매핑 표현 방법 비교
   - `owl:equivalentClass` vs `skos:exactMatch` vs `rdfs:subClassOf` 사용 기준

4. 자동 매핑 실패 사례
   - 기존 본문의 "의미적 이질성" 설명을 구체적 실패 사례로 증명

**삽입 위치**: "자동 매핑의 현실적 성능" 섹션 뒤, "반자동 매핑의 현실적 프로세스" 섹션 전

**의존성**: 없음 (독립적)

**리스크**:
- 기존 본문의 도구 설명과 중복 위험
  - 완화: 기존은 "도구 소개"이고, 이 보강은 "도구 사용 과정"으로 역할 분리
- 의료 도메인 지식 정확성
  - 완화: "개념 이해를 위한 간소화된 예시" 주석 포함

## 기술 접근법

### 공통 원칙

- **기존 엔티티 재사용**: 각 파일에서 이미 사용 중인 예시(홍길동, 병원 A/B 등)를 재사용하여 학습자 인지 부하 최소화
- **Turtle 코드 블록**: 모든 온톨로지 예제는 Turtle 형식 사용
- **"간소화 주석"**: 실제 운영 수준이 아닌 교육용 예제임을 명시
- **연결 포인트 callout**: 각 보강 섹션에 1개 이상의 cross-phase 연결 포함

### 문체 가이드라인

- `content/phase-1/01-motivation.mdx`의 톤 참조: 존댓말 + 친근한 멘토
- `content/phase-8/05-decision-tree.mdx`의 구조 참조: 의사결정 노드별 정/부 예시
- 기술 용어는 영어 원문 + 한국어 병기: "엔티티 해소(Entity Disambiguation)"

### 품질 기준

- 파일당 추가 분량: 60~120줄 목표
- "왜 필요한가?" blockquote: 파일당 1개 이상
- "연결 포인트" callout: 파일당 1개 이상
- Mermaid 다이어그램: 필요시 (REQ-P4P8-001에서 3계층 비교 다이어그램 권장)
