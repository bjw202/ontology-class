## 기본 실습

### 기본 실습 1: OWA를 활용한 추론 예시 3가지 작성

**목표:** 개방 세계 가정(OWA)이 실제 시나리오에서 어떻게 다른 결론을 이끌어내는지 이해합니다.

**과제:** 아래 시나리오마다 CWA와 OWA에서 각각 어떤 결론이 나오는지 작성하세요.

**시나리오 A: 학술 데이터베이스**

연구자 '박교수'의 논문 데이터:
```
hasPublished(:ParkProfessor, :Paper2023AI)
hasPublished(:ParkProfessor, :Paper2022ML)
```

질문: "박교수가 온톨로지 분야 논문을 발표한 적이 있는가?"

- **CWA 결론:** _______________
- **OWA 결론:** _______________
- **어떤 가정이 더 적합한가 (그 이유):** _______________

**시나리오 B: 소셜 네트워크**

소셜 그래프 데이터:
```
isFriendWith(:Alice, :Bob)
isFriendWith(:Alice, :Carol)
```

질문: "Alice와 Dave는 친구인가?"

- **CWA 결론:** _______________
- **OWA 결론:** _______________
- **어떤 가정이 더 적합한가 (그 이유):** _______________

**시나리오 C: 약물 상호작용 온톨로지**

약물 데이터:
```
interactsWith(:DrugA, :DrugB)
```

질문: "DrugA와 DrugC는 상호작용이 없는가?"

- **CWA 결론:** _______________
- **OWA 결론:** _______________
- **어떤 가정이 더 적합한가 (그 이유):** _______________

**모범 답안 힌트:**
- 시나리오 A: 데이터에 없으면 발표 안 했음(CWA) vs. 발표했을 수도 있음(OWA). 학술 DB는 완전하지 않으므로 OWA가 더 적합
- 시나리오 B: 데이터에 없으면 친구 아님(CWA) vs. 알 수 없음(OWA). SNS는 모든 관계를 기록하므로 CWA가 실용적
- 시나리오 C: 안전에 관한 정보이므로 OWA가 중요 — "모른다"와 "없다"는 다름

### 기본 실습 2: 독신자를 DL 표현식으로 작성하기

**목표:** DL 표현식을 이해하고 자연어 정의를 형식적으로 변환할 수 있습니다.

**과제:** "독신자(Bachelor)는 결혼하지 않은 성인 남성"을 DL 표현식으로 작성하세요.

**단계별 가이드:**

1단계: 필요한 개념과 역할 식별하기
- 개념: `Adult`, `Male`, `Person`, `Married` (이미 존재한다고 가정)
- 역할: 직접적인 역할은 없음

2단계: 각 조건을 DL로 변환하기
- "성인 남성" = _______________
- "결혼하지 않은" = _______________

3단계: 완전 정의 작성하기
```
Bachelor ≡ _______________
```

**추가 질문:**

a) 위 정의에서 `Bachelor ≡` (등치, equivalence)를 사용했습니다. 만약 `Bachelor ⊑` (포함, subsumption)을 사용한다면 어떤 차이가 있나요?

b) OWA 하에서, "결혼 기록이 없는 성인 남성"을 독신자로 자동 추론할 수 있나요? 그 이유는?

c) `∃hasSpouse.Person`을 사용하여 "배우자가 있는 것(Married)"을 정의해보세요.

**모범 답안:**
```
Married ≡ ∃hasSpouse.Person
Bachelor ≡ Adult ⊓ Male ⊓ ¬Married
```

또는:
```
Bachelor ≡ Adult ⊓ Male ⊓ ¬(∃hasSpouse.Person)
```

**주의:** OWA 하에서 결혼 기록이 없다고 독신자로 추론할 수 **없습니다**. `¬Married`를 명시적으로 선언해야 합니다.

### 도전 실습 1: 작은 온톨로지에서 4가지 추론 유형 각각 적용하기

**목표:** 4가지 추론 유형을 실제 온톨로지에 적용하여 각각의 역할을 이해합니다.

**주어진 온톨로지 (가족 관계):**

TBox:
```
Parent ≡ ∃hasChild.⊤
GrandParent ≡ ∃hasChild.Parent
Father ≡ Parent ⊓ Male
GrandFather ≡ GrandParent ⊓ Male
Ancestor ≡ Parent ⊔ ∃hasParent⁻.Ancestor
Male ⊑ ¬Female
```

ABox:
```
Male(:John)
Male(:Mike)
Female(:Sarah)
Female(:Emma)
hasChild(:John, :Mike)
hasChild(:Mike, :Emma)
hasChild(:Sarah, :Emma)
```

**각 추론 유형을 적용하세요:**

**1. 일관성 검사 (Consistency Checking):**

위 온톨로지를 분석하여:
a) 모순이 있는지 확인하세요
b) 만약 `Female(:John)`을 ABox에 추가하면 어떻게 되는가?
c) 그 모순의 논리적 이유를 설명하세요

**2. 개념 분류 (Concept Classification):**

다음 포함 관계들이 TBox에서 자동으로 계산되는지 확인하세요:
a) `Father ⊑ Parent`: (예/아니오, 이유): _______________
b) `GrandFather ⊑ Father`: (예/아니오, 이유): _______________
c) `GrandFather ⊑ GrandParent`: (예/아니오, 이유): _______________
d) 이 포함 관계들이 TBox에 명시되어 있지 않아도 추론기가 계산하는 이유는?: _______________

**3. 인스턴스 인식 (Instance Recognition):**

각 개체(:John, :Mike, :Sarah, :Emma)가 속하는 클래스를 추론하세요:

| 개체 | 명시된 클래스 | 추론된 클래스 | 추론 근거 |
|------|------------|------------|---------|
| :John | Male | Parent, Father, GrandParent, GrandFather | hasChild(:John, :Mike) 있음 + Male |
| :Mike | Male | _____ | _____ |
| :Sarah | Female | _____ | _____ |
| :Emma | Female | _____ | _____ |

**4. 개념 충족 가능성 (Concept Satisfiability):**

다음 개념들이 공허(unsatisfiable)한지 분석하세요:

a) `FemaleGrandFather ≡ GrandFather ⊓ Female`
- 공허한가?: _______________
- 이유: _______________

b) `PersonWithoutParent ≡ Person ⊓ ¬∃hasChild⁻.Person`
- 이것이 공허한가?: _______________
- (힌트: OWA를 고려하세요)

c) `ParentAndChild ≡ Parent ⊓ ∃hasChild.Parent`
- 공허한가?: _______________
- 이유: _______________

### 도전 실습 2: SNOMED CT가 OWL 2 EL을 선택한 이유 분석

**목표:** 실제 대규모 온톨로지의 기술 결정을 논리적으로 분석할 수 있습니다.

**배경 정보:**
- SNOMED CT(Systematized Nomenclature of Medicine Clinical Terms)는 의학 임상 용어의 표준 온톨로지
- 약 350,000개 이상의 개념(Concept), 100만 개 이상의 관계(Relationship) 포함
- 전 세계 85개 이상 국가에서 의료 기록에 사용
- 2012년 이전: OWL 2 DL 기반으로 개발 시도
- 2012년 이후: OWL 2 EL로 마이그레이션

**분석 과제:**

**Part A: 기술적 분석 (200자 이상)**

1. SNOMED CT의 주요 지식 패턴을 분석하세요:
   - "폐렴(Pneumonia)은 폐(Lung)를 침범 부위(findingSite)로 하는 감염성 폐 질환이다"
   - 이 정보를 OWL 2 EL로 표현할 수 있는가? 어떻게?
   - 전칭 제한(`∀`)이 반드시 필요한 SNOMED CT 지식이 있는가?

2. 성능 분석:
   - OWL 2 DL 전체를 사용하면 어떤 추론 복잡도인가?
   - OWL 2 EL로 제한하면 복잡도가 어떻게 바뀌는가?
   - 350,000개 개념 분류에서 이 차이는 실용적으로 얼마나 중요한가?

**Part B: 트레이드오프 평가 (150자 이상)**

OWL 2 EL 선택으로 포기한 것들:
- 어떤 OWL 2 DL 기능을 사용할 수 없게 되었는가?
- 이 기능들이 SNOMED CT의 핵심 사용 사례에 필요한가?
- "포기한 기능의 가치"와 "얻은 성능 이득"을 어떻게 평가하는가?

**Part C: 대안 설계 제안 (100자 이상)**

만약 SNOMED CT를 처음부터 설계한다면:
- 동일한 OWL 2 EL을 선택하겠는가?
- 다른 접근법이 있다면 무엇인가? (예: 하이브리드 아키텍처)

**참고 자료:**
- Baader et al. (2005), "Pushing the EL Envelope" — EL++ 알고리즘의 원논문
- Bodenreider et al. (2021), "Is the SNOMED CT content in OWL EL?"
- ELK 추론기 공식 사이트 (liveontologies.github.io/elk-reasoner/)

### 도전 실습 3: 자신만의 소규모 온톨로지 설계

**목표:** 3단계에서 배운 모든 개념을 종합하여 실용적인 소규모 온톨로지를 설계합니다.

**과제:** 다음 도메인 중 하나를 선택하여 OWL 2 EL 범위 안의 온톨로지를 설계하세요.

선택지:
- 도서관 분류 시스템
- 식품 영양 분류
- 도시 교통 네트워크

**설계 요건:**

1. **TBox 설계 (최소 10개 클래스, 5개 관계)**
   - 최소 3개의 완전 정의(≡)와 2개의 필요조건 정의(⊑) 포함
   - 역할 체인 1개 이상 포함

2. **ABox 설계 (최소 10개 개체)**
   - 명시적으로 분류되지 않은 개체 3개 이상 포함 (추론기가 자동 분류하도록)

3. **추론 시나리오 기술**
   - 일관성 검사: 어떤 모순이 가능한가?
   - 개념 분류: 어떤 포함 관계가 자동 계산되는가?
   - 인스턴스 인식: 어떤 개체가 자동 분류되는가?

4. **OWA 고려사항 기술**
   - 이 도메인에서 OWA가 어떤 설계 결정을 이끌어내는가?

5. **프로파일 선택 근거**
   - OWL 2 EL, QL, RL 중 왜 선택했는가?

**평가 기준:**
- DL 표현식의 정확성
- OWA에 대한 이해도
- 추론 시나리오의 구체성
- 프로파일 선택의 논리적 근거
