## 왜 벡터 임베딩을 온톨로지와 비교해야 하는가?

> "2013년 Word2Vec 등장 이후, 많은 전문가들이 '온톨로지의 시대가 끝났다'고 예언했습니다. 하지만 현실은 더 미묘합니다."

최근 AI/ML의 발전으로 벡터 임베딩(Vector Embeddings)이 지식 표현의 강력한 대안으로 부상했습니다. 특히 대형 언어 모델(LLM)의 등장으로 이 논쟁은 더욱 뜨거워졌습니다.

온톨로지를 공부한 사람이라면 반드시 이 비교를 이해해야 합니다. 프로젝트에서 어떤 접근법을 선택할지 결정하는 데 핵심적인 지식이기 때문입니다.

## 벡터 임베딩(Vector Embeddings)이란?

벡터 임베딩은 단어, 개념, 또는 개체를 고차원 실수 벡터로 표현하는 방법입니다.

**핵심 아이디어:**
- 의미가 비슷한 개념은 벡터 공간에서 가까이 위치
- 유사도를 코사인 유사도(Cosine Similarity) 등으로 수치화
- 대규모 텍스트나 그래프 데이터에서 자동으로 학습

예시: `King - Man + Woman = Queen` (Word2Vec의 유명한 예)

## 온톨로지 vs 벡터 임베딩: 상세 비교

### 온톨로지의 강점

**1. 명시적 의미론 (Explicit Semantics)**

온톨로지는 모든 개념과 관계를 명시적으로 정의합니다. "왜 이 결론에 도달했는가?"를 논리적으로 설명할 수 있습니다.

의료 진단 시스템에서 "이 환자는 X 질병일 가능성이 있습니다"라는 결론이 나왔을 때, 온톨로지 기반 시스템은 어떤 증상, 어떤 규칙, 어떤 논리적 경로를 통해 이 결론에 도달했는지 설명할 수 있습니다.

**2. 논리적 추론 가능성 (Logical Inference)**

기술된 사실에서 새로운 사실을 논리적으로 도출할 수 있습니다:
- "A는 B의 하위 클래스이고, B는 C의 특성을 가진다 → A도 C의 특성을 가진다"
- 모순 감지 가능
- 완전성(Completeness) 추론 가능

**3. 도메인 지식 정확한 표현**

전문가의 지식을 왜곡 없이 형식화할 수 있습니다. 모호성이 없고, 여러 시스템 간 공유 가능한 표준 어휘를 제공합니다.

**4. 상호운용성 (Interoperability)**

RDF/OWL 표준을 따르는 온톨로지는 서로 다른 시스템, 조직, 심지어 언어를 사용하는 파트너와도 공유하고 통합할 수 있습니다.

### 벡터 임베딩의 강점

**1. 낮은 구축 비용**

온톨로지처럼 전문가가 수동으로 개념을 정의할 필요가 없습니다. 대규모 텍스트 코퍼스에서 자동으로 학습합니다. Wikipedia 전체를 임베딩으로 변환하는 데 몇 시간이면 충분합니다.

**2. 통계적 패턴 포착**

언어와 지식의 미묘한 패턴을 포착합니다. 온톨로지가 명시적으로 정의하지 않은 관계도 통계적으로 발견합니다.

**3. 유사도 계산 용이**

두 개념의 의미적 유사도를 수치로 계산할 수 있습니다. 이는 정보 검색, 추천 시스템에서 매우 유용합니다.

**4. 확장성과 유연성**

새로운 개념을 추가해도 전체 시스템을 재설계할 필요가 없습니다. 연속 벡터 공간에서 자연스럽게 통합됩니다.

### 핵심 비교 매트릭스

| 특성 | 온톨로지 | 벡터 임베딩 |
|------|--------|-----------|
| 설명 가능성 | 높음 (논리적 추론 경로) | 낮음 ("블랙박스") |
| 구축 비용 | 높음 (전문가 필요) | 낮음 (자동 학습) |
| 추론 능력 | 형식적 논리 추론 | 통계적 패턴 |
| 정밀도 | 높음 (명시적 정의) | 가변적 (통계적) |
| 확장성 | 어려움 (수동 작업) | 쉬움 (자동 학습) |
| 모호성 처리 | 어려움 (명확성 요구) | 쉬움 (확률적) |
| 상호운용성 | 높음 (표준 기반) | 낮음 (모델 의존) |
| 오류 감지 | 가능 (모순 감지) | 어려움 |

## 하이브리드 접근법: 두 세계의 최선

> "온톨로지를 버리고 벡터 임베딩만 쓰는 것도, 벡터 임베딩을 무시하고 온톨로지만 쓰는 것도 최선이 아닙니다. 하이브리드가 종종 최선입니다."

### RDF2Vec

온톨로지의 RDF 그래프를 그래프 탐색(Random Walk)으로 변환하여 Word2Vec으로 임베딩합니다.

**작동 원리:**
1. RDF 그래프에서 무작위 경로(Random Walk) 생성
2. 각 경로를 "문장"처럼 처리
3. Word2Vec으로 노드를 벡터로 변환

**장점:** 온톨로지의 구조적 정보를 벡터로 인코딩
**단점:** 논리적 의미론은 손실됨

### OWL2Vec

OWL의 논리적 공리(Axiom)를 임베딩에 포함시키는 더 발전된 접근법입니다.

**작동 원리:**
1. OWL 공리를 자연어 문장으로 변환
2. 문장 임베딩 모델로 학습
3. 온톨로지 추론 결과도 포함

**장점:** 논리적 의미론의 일부를 보존

### 지식 그래프 임베딩 (Knowledge Graph Embeddings)

**TransE:** 관계(Relation)를 벡터 공간에서의 변환(Translation)으로 모델링
- `head + relation = tail` (h + r ≈ t)
- 간단하고 효과적

**RotatE:** 관계를 복소수 공간에서의 회전으로 모델링
- TransE보다 복잡한 관계 패턴 포착 가능
- 대칭, 반대칭, 역관계 등 표현

**ComplEx:** 복소수 벡터 공간 사용
- 비대칭 관계 잘 처리

### 온톨로지 + LLM 하이브리드

최근 가장 주목받는 접근법으로, 온톨로지로 LLM의 환각(Hallucination)을 제어합니다.

**패턴:** 온톨로지가 사실의 스캐폴드를 제공하고, LLM이 자연어 이해와 생성을 담당합니다.

예: 의료 대화 시스템에서 SNOMED CT 온톨로지가 의학적으로 올바른 개념과 관계를 보장하고, LLM이 자연스러운 대화를 생성합니다.

## 연결 포인트

> 벡터 임베딩이 강점을 발휘하는 시나리오와 온톨로지가 강점을 발휘하는 시나리오를 이해했다면, 다음 회차에서 배울 기술 비교 매트릭스가 더욱 명확하게 이해됩니다. 특히 "언제 어떤 기술을 선택하는가"라는 질문에 이 회차의 내용이 핵심 근거가 됩니다.

> 1회차에서 배운 비용 분석을 이 맥락에 적용해보면: 벡터 임베딩은 구축 비용이 낮지만 설명 가능성이 낮고, 온톨로지는 구축 비용이 높지만 설명 가능성이 높습니다. 도메인과 요구사항에 따라 이 트레이드오프를 판단해야 합니다.

## 흔한 오해

### 오해 1: "ChatGPT가 있으니 온톨로지는 필요 없다"

LLM은 강력하지만 환각(Hallucination) 문제가 있습니다. 의료, 법률, 금융 같은 분야에서는 "그럴듯한 거짓"이 치명적입니다. 온톨로지는 LLM의 답변을 검증하고 제한하는 역할을 합니다. 두 기술은 경쟁이 아니라 협력 관계입니다.

### 오해 2: "벡터 임베딩이 더 현대적이니까 온톨로지보다 더 좋다"

"더 현대적"이 "더 좋다"를 의미하지 않습니다. 각 기술은 서로 다른 문제를 해결합니다. 다중 언어 유사도 검색에는 임베딩이 더 좋고, 형식적 추론과 표준화된 지식 공유에는 온톨로지가 더 좋습니다.

### 오해 3: "RDF2Vec 같은 하이브리드가 있으니 온톨로지를 임베딩으로 변환하면 된다"

하이브리드는 유용하지만 온톨로지의 모든 특성을 보존하지 못합니다. 특히 논리적 추론 능력과 모순 감지 능력은 임베딩으로 변환하면 손실됩니다.

## 실제 프로젝트에서의 선택 가이드

어떤 기술을 선택할지 결정할 때 다음 질문을 자문하세요:

**온톨로지를 선택해야 할 때:**

- "이 결정이 왜 이루어졌는지 설명할 수 있어야 한다" (XAI, Explainable AI 요구)
- "의료, 법률, 금융처럼 오류 허용성이 낮다"
- "여러 조직이 같은 지식 기반을 공유해야 한다"
- "새로운 사실을 논리적으로 도출해야 한다"

**벡터 임베딩을 선택해야 할 때:**

- "의미 기반 검색이 핵심이다" (의미가 유사한 문서 찾기)
- "대규모 비정형 텍스트에서 패턴을 찾아야 한다"
- "빠르게 구축해야 하고 설명 가능성은 덜 중요하다"
- "통계적 유사도만으로도 충분하다"

**하이브리드를 선택해야 할 때:**

- "구조화된 지식과 비정형 텍스트를 함께 처리해야 한다"
- "온톨로지의 정확성과 임베딩의 유연성이 모두 필요하다"
- "LLM을 사용하되 환각을 제어해야 한다"

## 최신 트렌드: LLM 시대의 온톨로지

> "ChatGPT, GPT-4 같은 대형 언어 모델(LLM)의 등장이 온톨로지의 역할을 어떻게 바꾸었는가?"

LLM은 놀라운 능력을 보여주지만 세 가지 근본적 한계가 있습니다:

**1. 환각(Hallucination):** 그럴듯하지만 사실이 아닌 정보를 생성합니다. 의료 분야에서는 치명적입니다.

**2. 지식 컷오프:** 학습 데이터 이후의 정보를 모릅니다. 온톨로지는 실시간 업데이트가 가능합니다.

**3. 추론 불투명성:** 왜 그 답을 냈는지 설명하기 어렵습니다. 온톨로지는 추론 경로를 추적합니다.

이 때문에 **온톨로지 + LLM** 하이브리드가 주목받습니다:

- **GraphRAG**: 지식 그래프(온톨로지)와 RAG(Retrieval-Augmented Generation)를 결합해 LLM의 환각을 줄이는 기법
- **온톨로지 기반 프롬프트**: LLM에게 온톨로지를 컨텍스트로 제공해 도메인 정확성 향상
- **검증 레이어**: LLM의 출력을 온톨로지로 검증해 사실 오류 필터링

이러한 발전은 온톨로지가 LLM 시대에도 여전히 중요한 역할을 한다는 것을 보여줍니다.

## 요약

온톨로지와 벡터 임베딩은 각각 고유한 강점을 가지며 서로 다른 문제를 해결합니다. 온톨로지는 설명 가능성, 논리적 추론, 표준화에 강하고, 벡터 임베딩은 낮은 구축 비용, 유사도 계산, 통계적 패턴 포착에 강합니다. RDF2Vec, OWL2Vec, 지식 그래프 임베딩 같은 하이브리드 접근법이 두 세계의 장점을 결합하려는 시도이며, LLM 시대에는 GraphRAG 같은 새로운 하이브리드 패턴이 등장하고 있습니다. 온톨로지와 LLM은 경쟁이 아닌 협력 관계입니다.
