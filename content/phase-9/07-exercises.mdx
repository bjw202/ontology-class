# 실습

## 심화 과제

<Exercise
  title="Python Action 패턴 구현"
  difficulty="advanced"
  duration="2~3일"
>
FastAPI + Pydantic으로 Palantir Action Type의 핵심 개념을 OSS 스택으로 재현합니다.

**출발점:** 6회차에서 소개한 `EscalateDefectAction` 코드 예시를 기반으로 다음을 추가 구현하세요.

**구현 요구사항:**

1. **유효성 검사 강화**: 유효성 검사 실패 시 구체적 오류 메시지 반환 (어떤 필드가, 왜, 어떻게 실패했는지)

2. **감사 로그 영속성**: 감사 로그를 SQLite 또는 PostgreSQL에 저장
   - 로그 항목: action_type, actor_id, target_id, timestamp, parameters, result
   - 조회 API: 특정 객체에 대한 모든 Action 이력 조회

3. **승인 워크플로우**: `critical` severity일 때 2단계 승인 구현
   - 1차 승인자: 직속 상관 (manager_id)
   - 2차 승인자: 안전 담당자 (safety_officer_id)
   - 승인 대기 중 상태 관리

4. **비동기 부수 효과**: Action 실행 후 이메일 또는 Slack 알림 발송 (실제 발송 불필요, mock 구현 가능)

**평가 기준:**
- Action 실행 시 감사 로그가 자동 기록되는가
- 권한 없는 Action 시도 시 거부되는가
- critical severity 시 2단계 승인 흐름이 올바른가
</Exercise>

<Exercise
  title="도메인 온톨로지 OWL vs Palantir 패턴 비교"
  difficulty="advanced"
  duration="3~5일"
>
자신의 업무 도메인에서 동일한 Competency Question 5개를 두 가지 방식으로 구현하고 비교 보고서를 작성합니다.

**구현 대상:**

**OWL 버전:**
- Protégé로 온톨로지 설계
- SPARQL로 Competency Question 5개 답하기
- HermiT 추론기로 일관성 검사

**Palantir 패턴 버전 (OSS 스택):**
- Pydantic 모델로 Object Type 정의
- SQLAlchemy로 Link Type 및 관계 구현
- FastAPI로 Action Type 구현 (유효성 검사 + 감사 로그)

**비교 보고서 항목:**
- 구현 코드 양 비교 (라인 수, 복잡도)
- 추론 능력 차이 (OWL Reasoner vs. Function 기반 계산)
- 거버넌스 구현 용이성 (접근 제어, 감사 로그)
- 확장성 (새로운 도메인 개념 추가 시)
- 어떤 상황에서 어느 방식이 더 적합한가

**도메인 선택 예시:** 레이저 공정 품질 관리, 병원 수술 일정 관리, 물류 창고 재고 관리 등
</Exercise>

<Exercise
  title="Mini-AIP 아키텍처 설계 및 구현"
  difficulty="advanced"
  duration="5~7일"
>
Python + LangGraph + FastAPI로 Palantir AIP의 핵심 개념을 구현합니다.

**구현 대상:**

1. **OntologyManager**: Object Type 스키마 등록 및 관리
   - Object Type 정의 (이름, 속성, 유효성 규칙)
   - Link Type 정의 (source, target, cardinality)
   - 스키마 버전 관리 (experimental → active → deprecated)

2. **ActionExecutor**: Action Type 정의 + 유효성 검사 + 감사 로그
   - Action 등록: 이름, 파라미터 스키마, 유효성 규칙, 권한 요구사항
   - Action 실행: 검증 → 실행 → 로그 → 결과 반환
   - Human-in-the-loop 옵션 (고위험 Action 시 사람 승인 요구)

3. **OntologyAgent** (LangGraph 기반):
   - data tool: 온톨로지 객체 쿼리 도구
   - logic tool: Function 실행 도구
   - action tool: Action 실행 요청 도구 (실제 실행은 ActionExecutor가 담당)

4. **SimpleOSDK**: Python 클라이언트 자동 생성
   - 등록된 Object Type에 대한 Pydantic 모델 자동 생성
   - 타입 안전한 쿼리 인터페이스

**평가 기준:**
- 에이전트가 자연어로 "고장 설비 리스트"를 조회할 수 있는가
- Action 실행 시 감사 로그가 자동 기록되는가
- 권한 없는 Action 시도 시 거부되는가
- 실행 결과가 다음 쿼리에 반영되는가 (닫힌 루프)
</Exercise>
