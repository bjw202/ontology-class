# 통합 실습: 설계 방법론 전체 적용

## 실습 목표

이 실습을 마치면 다음을 할 수 있습니다.

- METHONTOLOGY 프로세스를 실제 문제에 적용할 수 있다.
- 역량 질문(CQ)을 작성하고 클래스/속성을 도출할 수 있다.
- 적절한 설계 전략을 선택하고 적용할 수 있다.
- 기존 온톨로지를 찾아 재사용할 수 있다.
- 안티패턴을 식별하고 수정할 수 있다.
- 5가지 품질 기준으로 온톨로지를 평가할 수 있다.

## 실습 1: 기본 — 대학교 도메인 역량 질문 작성

### 배경

여러분은 대학교 수강 관리 시스템을 위한 온톨로지를 개발하는 팀에 합류했습니다. 팀장이 처음 해야 할 일로 역량 질문(CQ) 작성을 요청했습니다.

### 과제

다음 조건을 모두 만족하는 **역량 질문 5개**를 작성하시오.

조건:
1. 각 CQ는 하나의 명확한 질문이어야 한다.
2. 각 CQ는 SPARQL로 표현 가능해야 한다.
3. 5개의 CQ 전체가 다음 사용 시나리오를 모두 포괄해야 한다.

필요한 사용 시나리오:
- 학생이 수강 신청한 과목 목록 확인
- 교수가 강의하는 과목에서 등록 학생 수 확인
- 특정 학과의 개설 과목 목록 조회
- 졸업 요건 충족 여부 확인 (이수 학점)
- 강의실 스케줄 조회 (특정 시간대 빈 강의실)

### 제출 형식

각 CQ에 대해 다음을 작성하시오:

| 항목 | 내용 |
|------|------|
| CQ 번호 | CQ1, CQ2, ... |
| 질문 | 한국어 자연어 질문 |
| 필요한 클래스 | 이 CQ에 필요한 클래스 목록 |
| 필요한 속성 | 이 CQ에 필요한 속성 목록 |
| SPARQL 패턴 | WHERE 절의 트리플 패턴 (가상의 URI 사용 가능) |

## 실습 2: 기본 — CQ에서 클래스와 속성 도출

### 배경

실습 1에서 작성한 CQ 5개를 기반으로 온톨로지의 초기 구조를 만들려고 합니다.

### 과제

실습 1의 CQ에서 **클래스와 속성을 체계적으로 도출**하시오.

**2-A: 클래스 목록 작성**

CQ들에서 명사구를 추출하여 클래스 후보를 식별하시오. 각 클래스에 대해:

| 클래스 이름 | 한국어 이름 | 정의 | 출처 CQ |
|------------|-----------|------|---------|
| Student | 학생 | 대학교에 재학 중인 사람 | CQ1, CQ2 |
| ... | ... | ... | ... |

**2-B: 속성 목록 작성**

CQ들에서 동사구를 추출하여 속성 후보를 식별하시오. 각 속성에 대해:

| 속성 이름 | 유형 | 도메인 | 범위 | 카디널리티 | 출처 CQ |
|----------|------|--------|------|-----------|---------|
| enrolledIn | ObjectProperty | Student | Course | 0..* | CQ1 |
| ... | ... | ... | ... | ... | ... |

**2-C: 클래스 계층 설계**

도출된 클래스들에 대해 Middle-out 전략을 적용하여 초기 클래스 계층 구조를 설계하시오. 필요한 상위 클래스와 하위 클래스를 추가하시오.

## 실습 3: 도전 — 소형 온톨로지 METHONTOLOGY로 설계

### 배경

실습 1-2의 결과를 바탕으로 실제 소형 온톨로지를 설계합니다. 이 실습은 METHONTOLOGY의 명세와 개념화 단계를 완성하는 것을 목표로 합니다.

### 과제

METHONTOLOGY의 처음 2단계를 완성하시오.

**단계 1: 명세(Specification) 문서 작성**

다음 항목을 포함한 명세 문서를 작성하시오.

- **목적**: 이 온톨로지를 왜 만드는가? (2-3문장)
- **범위**: 포함되는 도메인과 제외되는 도메인 (각 3개 이상)
- **수준**: OWL 2 DL, 반형식적, 비형식적 중 선택과 이유
- **대상 사용자**: 누가 이 온톨로지를 사용하는가?
- **사용 시나리오**: 구체적인 사용 방법 2개
- **역량 질문(CQ)**: 실습 1에서 작성한 CQ 5개

**단계 2: 개념화(Conceptualization) 산출물 작성**

METHONTOLOGY 개념화 단계의 4가지 산출물을 작성하시오.

산출물 2-1: **용어 목록(Glossary of Terms)**
- 최소 10개 용어
- 각 용어: 이름, 유형(클래스/속성/인스턴스), 정의, 동의어(있으면)

산출물 2-2: **개념 분류표(Concept Classification Tree)**
- 클래스 간의 계층 구조를 트리 형식으로 표현
- rdfs:subClassOf 관계 명시

산출물 2-3: **이진 관계 표(Binary Relation Table)**

| 관계 이름 | 도메인 | 범위 | 카디널리티 | 역방향(있으면) |
|----------|--------|------|-----------|--------------|
| enrolledIn | Student | Course | 0..* | hasStudent |

산출물 2-4: **인스턴스 속성 표(Instance Attribute Table)**

각 클래스에 대해:

| 속성 이름 | 데이터 타입 | 카디널리티 | 예시 값 |
|----------|------------|-----------|---------|

## 실습 4: 도전 — 기존 온톨로지에서 안티패턴 찾고 수정

### 배경

다음은 학생들이 자주 작성하는 전형적인 온톨로지 설계입니다. 여러 안티패턴이 포함되어 있습니다.

### 문제 온톨로지

**클래스 목록**:
- ProfessorTeachingMorning (오전에 강의하는 교수)
- ProfessorTeachingAfternoon (오후에 강의하는 교수)
- ProfessorTeachingEvening (저녁에 강의하는 교수)
- FullTimeProfessor (전임 교수)
- PartTimeProfessor (비전임 교수)
- FullTimeMaleProfessor (남성 전임 교수)
- FullTimeFemaleProfessor (여성 전임 교수)
- TeachingActivity (강의 활동)
- CourseTitle (강의 제목)
- ProfessorRank (교수 직급)

**속성 목록**:
- hasTeachingTime (Professor → TimeSlot)
- teachesAt (Professor → TimeSlot, hasTeachingTime의 역방향으로 선언됨)
- teachesCourse (Professor → Course)
- isTaughtBy (Course → Professor, teachesCourse의 역방향으로 선언됨)
- hasCourseTitle (Course → CourseTitle)
- hasProfessorRank (Professor → ProfessorRank)

### 과제

**4-A: 안티패턴 식별**

위 온톨로지에서 발견되는 모든 안티패턴을 찾아 다음 표를 완성하시오.

| 번호 | 요소 | 안티패턴 유형 | 왜 안티패턴인가? |
|------|------|--------------|----------------|
| 1 | ProfessorTeachingMorning 클래스 | 과도한 클래스화 | ... |

**4-B: 수정된 온톨로지 설계**

식별된 모든 안티패턴을 수정한 새로운 온톨로지를 설계하시오.

수정된 설계에 포함할 것:
- 클래스 목록 (수정 및 삭제 이유 포함)
- 속성 목록 (수정 및 삭제 이유 포함)
- 수정 전과 수정 후의 대응 관계

**4-C: 수정 전후 비교**

수정 전과 수정 후를 비교하여 다음을 설명하시오:
- 클래스 수 변화: 이전 XX개 → 이후 XX개
- 속성 수 변화: 이전 XX개 → 이후 XX개
- 개선된 품질 차원: 어떤 차원이 어떻게 개선되었는가?
- 표현력 변화: 수정 후에도 원래의 정보를 모두 표현할 수 있는가?

## 평가 기준

| 실습 | 배점 | 핵심 평가 항목 |
|------|------|--------------|
| 실습 1 | 20점 | CQ의 구체성, SPARQL 표현 가능성, 사용 시나리오 포괄 여부 |
| 실습 2 | 25점 | 클래스/속성 도출의 정확성, 계층 구조의 논리성 |
| 실습 3 | 30점 | METHONTOLOGY 각 산출물의 완성도와 일관성 |
| 실습 4 | 25점 | 안티패턴 식별의 정확성, 수정안의 타당성 |

## 자가 점검 체크리스트

제출 전 다음 항목을 확인하시오.

**역량 질문 관련**:
- [ ] 각 CQ는 하나의 명확한 질문인가?
- [ ] 각 CQ는 SPARQL의 WHERE 절로 표현 가능한가?
- [ ] 5개의 CQ가 모든 사용 시나리오를 포괄하는가?

**클래스/속성 도출 관련**:
- [ ] 모든 클래스는 PascalCase를 따르는가?
- [ ] 모든 속성은 camelCase를 따르는가?
- [ ] 각 속성의 도메인과 범위가 명시되어 있는가?

**METHONTOLOGY 설계 관련**:
- [ ] 명세 문서의 모든 항목이 작성되었는가?
- [ ] 용어 목록에 최소 10개 이상의 용어가 있는가?
- [ ] 개념 분류표에 rdfs:subClassOf 관계가 명시되어 있는가?

**안티패턴 관련**:
- [ ] 모든 안티패턴 유형을 문서에 명시했는가?
- [ ] 수정된 온톨로지에서 같은 안티패턴이 반복되지 않는가?
- [ ] 수정 후에도 원래의 정보를 모두 표현할 수 있는가?
