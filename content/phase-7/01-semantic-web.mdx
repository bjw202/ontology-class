## Tim Berners-Lee의 시맨틱 웹 비전

### 웹의 아버지가 꿈꾼 미래

2001년, 월드와이드웹(WWW)을 발명한 Tim Berners-Lee는 Scientific American에 획기적인 논문을 발표했습니다. 논문의 제목은 "The Semantic Web"이었고, 그 내용은 당시로서는 매우 혁신적이었습니다.

그의 비전을 한 문장으로 요약하면: **"현재의 웹이 문서들을 연결한다면, 시맨틱 웹은 데이터를 연결한다."**

논문에서 그는 한 가지 미래 시나리오를 제시했습니다. 의사가 환자의 약물 정보를 검색할 때, 단순히 약품명을 검색하는 것이 아니라 "이 환자의 알레르기 이력을 고려했을 때 안전한 대체 약물은?"이라는 복잡한 질문에 컴퓨터가 자동으로 답할 수 있는 세상을 꿈꿨습니다.

이를 위해서는 웹의 정보가 단순한 텍스트가 아니라 **의미(Meaning)를 담은 구조화된 데이터**여야 한다고 주장했습니다.

### 시맨틱 웹 기술 스택

Tim Berners-Lee는 시맨틱 웹을 위한 기술 스택을 "레이어 케이크(Layer Cake)" 구조로 제시했습니다:

| 레이어 | 기술 | 역할 |
|--------|------|------|
| 신뢰(Trust) | 암호학, 검증 | 정보의 신뢰성 보장 |
| 증명(Proof) | 추론 엔진 | 결론의 근거 제시 |
| 논리(Logic) | OWL, Rule | 복잡한 추론 |
| 온톨로지(Ontology) | OWL, RDFS | 개념과 관계 정의 |
| 데이터(Data) | RDF, RDFS | 구조화된 데이터 |
| 식별(URI) | URI/IRI | 모든 것에 고유 ID |
| 기반(Foundation) | XML, Unicode | 문자와 구조 |

우리가 앞서 학습한 RDF, RDFS, OWL은 바로 이 기술 스택의 핵심 레이어들입니다.

> **왜 필요한가? - 시맨틱 웹 기술 스택의 의미**
> 단순히 기술을 배우는 것이 아니라, 각 기술이 더 큰 그림의 어느 부분을 담당하는지 이해하는 것이 중요합니다. SPARQL은 RDF 레이어에서 데이터를 쿼리하는 도구이고, OWL은 온톨로지 레이어에서 개념을 정의하는 언어입니다.

## 5스타 링크드 데이터 등급 체계

Tim Berners-Lee는 2010년에 **5스타 오픈 데이터(5-Star Open Data)** 체계를 제안했습니다. 이는 데이터가 얼마나 "링크드 데이터"의 이상에 가까운지를 평가하는 실용적인 척도입니다.

### ⭐ 1스타: 웹에 공개된 데이터

가장 기본 단계. 데이터를 어떤 형식으로든 인터넷에 공개합니다. 오픈 라이선스(Open License)만 있으면 됩니다.

예시: 정부 통계 보고서를 PDF로 웹사이트에 올리는 것.

한계: 기계가 자동으로 처리하기 어렵습니다. PDF 내부의 표를 프로그램이 읽으려면 복잡한 파싱이 필요합니다.

### ⭐⭐ 2스타: 구조화된 기계 판독 가능 데이터

데이터를 구조화된 기계 판독 가능(Machine-Readable) 형식으로 제공합니다.

예시: 정부 통계를 Excel(.xls) 파일로 공개하는 것.

한계: Excel은 독점 포맷(Proprietary Format)입니다. Microsoft Office 없이는 완전한 접근이 어렵습니다.

### ⭐⭐⭐ 3스타: 비독점 오픈 포맷

독점 소프트웨어 없이 접근 가능한 오픈 포맷을 사용합니다.

예시: Excel 대신 CSV(Comma-Separated Values)나 XML로 데이터를 제공하는 것.

한계: 데이터가 구조화되어 있지만, 다른 데이터셋과 연결하기 어렵습니다. "서울"이라는 도시가 다른 데이터셋의 "Seoul"과 같다는 것을 기계가 알 수 없습니다.

### ⭐⭐⭐⭐ 4스타: W3C 표준 사용

W3C가 정의한 표준(RDF, SPARQL)을 사용합니다. 각 자원(Resource)에 고유한 URI가 부여됩니다.

예시: 서울시 인구 데이터를 RDF 형식으로 제공하고, 각 지역구에 고유한 URI를 부여하는 것.

```
<http://data.seoul.go.kr/resource/district/Gangnam>
    rdfs:label "강남구"@ko ;
    ex:population 551000 ;
    ex:area "39.5 km2" .
```

한계: 아직 고립된 데이터입니다. 외부 데이터셋과 연결되지 않았습니다.

### ⭐⭐⭐⭐⭐ 5스타: 다른 데이터와 연결

최고 단계. 자신의 데이터를 외부 데이터셋과 연결(Link)합니다. 이것이 진정한 <strong>링크드 데이터(Linked Data)</strong>입니다.

예시: 서울시 강남구 데이터를 DBpedia의 강남구 항목(`http://dbpedia.org/resource/Gangnam_District`)과 연결하는 것.

```
<http://data.seoul.go.kr/resource/district/Gangnam>
    rdfs:label "강남구"@ko ;
    ex:population 551000 ;
    owl:sameAs <http://dbpedia.org/resource/Gangnam_District> ;
    owl:sameAs <http://www.wikidata.org/entity/Q484603> .
```

이제 이 데이터는 글로벌 지식 네트워크의 일부가 됩니다.

> **연결 포인트:** 6단계에서 학습한 `owl:sameAs` 속성이 바로 5스타 링크드 데이터를 만드는 핵심 도구입니다. 두 URI가 같은 실체(Entity)를 가리킴을 선언함으로써 데이터를 연결합니다.

## 주요 링크드 오픈 데이터 프로젝트

### DBpedia: Wikipedia의 구조화

DBpedia는 Wikipedia의 비구조화된 텍스트에서 구조화된 RDF 데이터를 추출하는 프로젝트입니다. 2007년 라이프치히 대학교와 베를린 자유대학교가 시작했습니다.

핵심 특징:
- Wikipedia의 인포박스(Infobox)를 RDF 트리플로 변환
- 수백만 개의 개체(Person, Place, Organization 등)를 포함
- SPARQL 엔드포인트를 통해 쿼리 가능
- 다른 링크드 데이터셋과 광범위하게 연결

예시: DBpedia에서 한국의 대통령 목록을 SPARQL로 조회할 수 있습니다.

### Wikidata: 위키미디어의 구조화된 지식베이스

Wikidata는 Wikipedia의 자매 프로젝트로, 2012년 위키미디어 재단이 시작했습니다. DBpedia가 Wikipedia를 "사후 변환"하는 것과 달리, Wikidata는 처음부터 구조화된 데이터로 직접 편집합니다.

핵심 특징:
- 언어 중립적인 항목(Item)과 속성(Property) 구조
- 모든 진술(Statement)에 출처(Reference) 제공 가능
- 다국어 레이블 지원 (한국어 포함)
- Wikipedia 인포박스의 주요 데이터 소스로 활용
- 공개 SPARQL 엔드포인트: `https://query.wikidata.org/`

Wikidata와 DBpedia의 차이를 이해하는 것이 중요합니다. Wikidata는 Wikipedia 편집자들이 직접 구조화된 데이터를 입력하는 "원천(Source)"이고, DBpedia는 Wikipedia 텍스트를 파싱하여 생성한 "파생물(Derivative)"입니다.

### Freebase: 구글이 인수한 지식베이스

Freebase는 2007년 Metaweb이 시작한 지식베이스로, 2010년 구글이 인수했습니다. 구글의 지식 그래프(Knowledge Graph) 구축의 기반이 되었으며, 2016년 Wikidata로 데이터를 이전하고 서비스를 종료했습니다.

역사적 의미: Freebase의 데이터 모델과 구글의 지식 그래프 구축 경험이 현재 대규모 지식 그래프 기술의 토대가 되었습니다.

## 링크드 오픈 데이터(LOD) 클라우드

링크드 오픈 데이터 클라우드는 전 세계에서 공개된 링크드 데이터셋들이 서로 연결된 거대한 네트워크입니다. 2009년에 처음 시각화되었으며, 현재는 수천 개의 데이터셋이 포함되어 있습니다.

주요 도메인별 데이터셋:
- **지리**: GeoNames, LinkedGeoData
- **과학**: Bio2RDF (생물정보학), ChemSpider (화학)
- **문화유산**: Europeana, 영국도서관
- **정부**: data.gov.uk, EU Open Data Portal
- **언어**: WordNet, Open Multilingual Wordnet

> **왜 필요한가? - LOD 클라우드의 가치**
> 개별 데이터셋은 작은 섬과 같습니다. 링크드 데이터의 마법은 이 섬들이 연결될 때 발생합니다. 당신의 데이터가 DBpedia, Wikidata, GeoNames와 연결되는 순간, 수백만 개의 다른 데이터셋이 제공하는 맥락을 자동으로 활용할 수 있게 됩니다.

## 한국의 공공 링크드 데이터 현황

### 공공데이터포털과 링크드 데이터

한국 정부는 공공데이터포털(data.go.kr)을 통해 수만 개의 공공 데이터셋을 제공하고 있습니다. 그러나 대부분의 데이터는 아직 CSV나 JSON 형식으로 제공되는 3스타 수준에 머물러 있습니다.

한국의 링크드 데이터 주요 이니셔티브:

- **국가 지식 포털**: 정부 관련 정보를 링크드 데이터 형식으로 제공하는 시범 프로젝트
- **한국 역사 지식 그래프**: 국사편찬위원회의 역사 데이터 연계 프로젝트
- **행정안전부 행정 표준 코드**: 법정동 코드, 기관 코드 등을 URI로 표준화

### 도전 과제

한국 공공 링크드 데이터가 직면한 주요 과제들:

1. **인식 부족**: 많은 데이터 담당자들이 링크드 데이터의 개념과 가치를 이해하지 못함
2. **기술 역량**: RDF, SPARQL 등 시맨틱 웹 기술에 능숙한 전문가 부족
3. **레거시 시스템**: 기존 관계형 데이터베이스 기반 시스템과의 통합 어려움
4. **유지보수**: 한 번 공개된 링크드 데이터를 지속적으로 갱신하는 비용

> **연결 포인트:** 한국 공공 링크드 데이터의 현 상태를 이해하는 것은 실전 적용에서 중요합니다. 정부 API와 데이터를 활용할 때, 그 데이터가 몇 스타 수준인지 파악하면 어떤 추가 작업(포맷 변환, URI 부여, 외부 연결)이 필요한지 계획할 수 있습니다.

> **왜 필요한가? - 5스타를 목표로 해야 하는 이유**
> 1스타와 5스타 데이터의 가치 차이는 엄청납니다. PDF로 제공되는 통계(1스타)는 사람이 직접 읽어야 하지만, 다른 데이터와 연결된 RDF(5스타)는 자동으로 분석하고, 다른 데이터와 결합하고, AI가 활용할 수 있습니다. 같은 데이터라도 개방성과 연결성이 높아질수록 가치가 기하급수적으로 증가합니다.

## 흔한 오해

### 오해 1: "시맨틱 웹은 실패한 프로젝트다"

2000년대 초반에 제안된 시맨틱 웹의 원래 비전이 완전히 실현되지 않은 것은 사실입니다. 그러나 "실패"라고 보는 것은 잘못된 해석입니다.

시맨틱 웹의 핵심 아이디어들은 다른 이름으로 살아남아 더 큰 영향력을 발휘하고 있습니다. 구글의 지식 그래프, Schema.org 마크업, Wikidata, 그리고 오늘날의 지식 그래프 기술은 모두 시맨틱 웹의 유산입니다.

### 오해 2: "링크드 데이터와 빅데이터는 반대 개념이다"

많은 사람들이 구조화된 작은 데이터인 링크드 데이터와 비구조화된 대용량 데이터인 빅데이터가 상충한다고 생각합니다. 그러나 실제로 두 접근법은 보완적입니다.

빅데이터는 대량의 데이터를 처리하는 기술을 제공하고, 링크드 데이터는 그 데이터에 의미와 맥락을 부여합니다. 최신 데이터 아키텍처에서는 두 기술을 함께 활용하는 경우가 많습니다.

### 오해 3: "시맨틱 웹은 AI/ML이 대체했다"

딥러닝과 LLM의 발전으로 시맨틱 웹이 불필요해졌다는 주장이 있습니다. 그러나 실제로는 정반대의 현상이 일어나고 있습니다. LLM의 한계(환각, 불투명한 추론, 지식 부정확성)를 보완하기 위해 구조화된 지식 그래프와 온톨로지가 더욱 중요해지고 있습니다. 이것이 바로 5회차에서 다룰 Graph RAG의 핵심 배경입니다.
