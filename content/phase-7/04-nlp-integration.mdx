> **왜 필요한가? - NLP와 온톨로지의 통합이 필요한 이유**
> NLP는 텍스트를 기계가 처리할 수 있게 변환하지만, 그 결과물은 여전히 언어적입니다. 온톨로지는 이 언어적 결과물을 구조화된 지식으로 전환하는 다리 역할을 합니다. NLP 없이는 대량의 비구조화 텍스트에서 지식을 추출할 수 없고, 온톨로지 없이는 그 결과를 의미 있게 정리할 수 없습니다.

## NLP의 기본 파이프라인

### 자연어 처리의 단계

자연어 처리는 텍스트를 컴퓨터가 분석할 수 있는 형태로 변환하는 과정입니다. 주요 단계를 살펴봅시다.

**1단계: 토큰화(Tokenization)**
문장을 단어(토큰) 단위로 분리합니다.
예: "이순신은 조선의 명장이다" → ["이순신", "은", "조선", "의", "명장", "이다"]

**2단계: 품사 태깅(POS Tagging, Part-of-Speech Tagging)**
각 단어의 품사를 식별합니다.
예: "이순신(고유명사)", "은(조사)", "조선(고유명사)", "의(조사)", "명장(명사)", "이다(서술격조사)"

**3단계: 개체명 인식(NER, Named Entity Recognition)**
텍스트에서 인명, 지명, 기관명, 날짜, 숫자 등을 인식합니다.
예: "이순신(인명)", "조선(국가명)"

**4단계: 구문 분석(Dependency Parsing)**
단어들 사이의 문법적 관계를 분석합니다.
예: "명장" ← "이다" ← "이순신" 구조 파악

**5단계: 의미 분석(Semantic Analysis)**
각 단어의 실제 의미와 문장 전체의 의미를 파악합니다. 여기서 온톨로지가 핵심 역할을 합니다.

## 개체명 인식(NER)과 온톨로지 연동

### NER의 기본 개념

NER(Named Entity Recognition)은 텍스트에서 고유한 실체를 식별하고 분류하는 기술입니다. 일반적인 NER 시스템은 다음과 같은 범주를 인식합니다:

- **PER (Person)**: 인명 - "이순신", "봉준호", "Bill Gates"
- **ORG (Organization)**: 기관명 - "삼성전자", "UNESCO", "서울대학교"
- **LOC (Location)**: 지명 - "서울", "한강", "백두산"
- **DATE**: 날짜 - "2024년 3월", "임진왜란"
- **NUM**: 숫자/금액 - "3억 달러", "100만 명"

### 온톨로지 연동: Entity Linking

NER가 텍스트에서 "이순신"을 인명으로 인식했다면, 다음 단계는 이것이 어떤 이순신인지 확인하는 것입니다. 이를 **개체 연결(Entity Linking)** 또는 <strong>위키데이터 연결(Wikidata Linking)</strong>이라고 합니다.

프로세스:
1. NER: "이순신"을 인명으로 인식
2. 후보 엔티티 생성: Wikidata/DBpedia에서 "이순신"을 이름으로 가진 엔티티 목록 조회
3. 모호성 해소: 문맥을 고려하여 가장 적합한 엔티티 선택 (조선 시대 장군)
4. 연결: Wikidata의 Q34597 (이순신)에 연결

이렇게 텍스트의 언급(Mention)을 온톨로지의 엔티티와 연결함으로써, 비구조화 텍스트가 구조화된 지식 그래프의 일부가 됩니다.

> **연결 포인트:** 이 과정이 바로 2회차에서 학습한 "지식 그래프 구축 방법 중 정보 추출"의 실제 메커니즘입니다. NER과 Entity Linking이 자동화된 지식 그래프 구축의 핵심 기술입니다.

### 의료 NER과 SNOMED CT

의료 분야의 NER은 특히 중요하고 도전적입니다. 의학 문헌에는 수만 개의 전문 용어, 약어, 복합어가 사용됩니다.

SNOMED CT (Systematized Nomenclature of Medicine - Clinical Terms)는 의료 분야에서 가장 널리 사용되는 임상 온톨로지입니다. 35만 개 이상의 의학 개념과 그 관계를 정의합니다.

의료 NER + SNOMED CT 연동의 흐름:
- 임상 기록 텍스트: "환자는 3년 전부터 HTN 진단받아 amlodipine 5mg 복용 중"
- NER: "HTN"(질환), "amlodipine 5mg"(약물), "3년 전"(시간)
- SNOMED CT 연결: "HTN" → SNOMED CT ID 38341003 (Hypertension)
- 약물 온톨로지 연결: "amlodipine" → DrugBank ID: DB00381

이를 통해 비구조화된 임상 기록에서 구조화된 의료 데이터를 추출할 수 있습니다.

## 관계 추출(Relation Extraction)

### 관계 추출이란?

관계 추출(RE, Relation Extraction)은 텍스트에서 엔티티 간의 관계를 자동으로 식별하는 기술입니다.

예시:
- 텍스트: "이재용은 삼성전자의 회장이다"
- 엔티티: "이재용"(인명), "삼성전자"(기관)
- 추출된 관계: (이재용, 직위, 삼성전자 회장), (이재용, 소속기관, 삼성전자)

이렇게 추출된 관계는 지식 그래프의 트리플로 변환됩니다.

### 관계 추출의 유형

**패턴 기반 관계 추출**: 미리 정의된 언어 패턴을 사용합니다.
예: "X는 Y의 CEO다" → (X, CEO, Y), "X가 Y를 설립했다" → (X, 설립, Y)

장점: 정확도가 높고 설명 가능
단점: 새로운 패턴을 수동으로 정의해야 함

**기계학습 기반 관계 추출**: 대량의 레이블된 데이터로 모델을 훈련합니다.

장점: 다양한 패턴 자동 학습
단점: 대량의 훈련 데이터 필요, 설명 어려움

**원격 감독(Distant Supervision)**: 기존 지식 그래프를 자동 레이블링에 활용합니다.

Wikidata에 (이순신, 태어난곳, 아산)이 있다면, "이순신"과 "아산"이 함께 등장하는 문장을 태어난 곳 관계 예시로 자동 수집합니다.

장점: 수동 레이블링 없이 대규모 훈련 데이터 구성 가능
단점: 잡음(Noise)이 포함될 수 있음

## 의미 역할 레이블링(Semantic Role Labeling)

### SRL이란?

의미 역할 레이블링(SRL, Semantic Role Labeling)은 문장의 각 요소가 어떤 의미적 역할을 하는지 분석합니다.

예시: "이순신이 임진왜란에서 왜군을 격파했다"
- Agent(행위자): 이순신
- Theme(대상): 왜군
- Location(장소): 임진왜란 (전투 맥락)
- Predicate(서술어): 격파하다

SRL은 "누가", "무엇을", "어디서", "어떻게"라는 질문에 답하는 것으로, 이벤트(Event)와 참여자(Participant)의 관계를 파악합니다.

### SRL과 온톨로지 통합

SRL의 결과를 FrameNet이나 PropBank 같은 의미역 온톨로지와 연결하면, 다양한 표현의 사건을 통일된 형태로 표현할 수 있습니다.

예: "이순신이 왜군을 격파했다", "이순신이 왜군을 물리쳤다", "왜군이 이순신에게 패배했다"는 모두 같은 사건을 다른 관점에서 표현한 것입니다. 온톨로지를 통해 이들을 동일한 사건의 다른 표현으로 통합할 수 있습니다.

## WordNet과 온톨로지

### WordNet이란?

WordNet은 프린스턴 대학교에서 개발한 영어 어휘 데이터베이스입니다. 단어들을 의미에 따라 동의어 집합(Synset)으로 묶고, 이 집합들 사이의 어휘 의미 관계를 정의합니다.

WordNet의 주요 관계:
- **IS-A (하위어, Hyponym)**: "강아지"는 "동물"이다
- **HAS-PART (부분어, Meronym)**: "자동차"는 "엔진"을 가진다
- **반의어 (Antonym)**: "행복" ↔ "불행"
- **유사어 (Synset)**: "자동차", "차", "승용차", "카"

### WordNet vs. 온톨로지

WordNet과 온톨로지는 유사해 보이지만 중요한 차이가 있습니다:

| 구분 | WordNet | 온톨로지 |
|------|---------|----------|
| 초점 | 언어적 의미 | 개념적 의미 |
| 관계 | 어휘 관계 | 도메인 관계 |
| 추론 | 제한적 | 풍부한 논리 추론 |
| 용도 | NLP, 의미 검색 | 지식 표현, 추론 |

WordNet은 NLP의 언어 처리 단계에서, 온톨로지는 지식 표현과 추론 단계에서 사용됩니다. 많은 시스템이 두 가지를 결합하여 활용합니다.

한국어 WordNet인 **KorLex**와 **KAIST의 한국어 개념 사전**이 있으며, 한국어 NLP 시스템에서 중요한 역할을 합니다.

> **왜 필요한가? - WordNet과 온톨로지를 함께 사용하는 이유**
> WordNet은 "사과"가 "과일"의 일종임을 알고 있지만, "사과"의 영양 성분, 생산지, 제철 시기 등 도메인 지식은 모릅니다. 온톨로지는 이런 도메인 특화 지식을 제공합니다. 두 가지를 결합하면 언어적 이해와 도메인 지식을 함께 활용할 수 있습니다.

## SNOMED CT + 의료 NLP

### SNOMED CT의 활용

6단계에서 이미 SNOMED CT를 학습했지만, 여기서는 NLP와의 통합 관점에서 다시 살펴봅니다.

SNOMED CT + NLP 파이프라인의 실제 적용:

의료 기록에서 자동으로 다음을 수행합니다:
- 임상 증상 추출 → SNOMED CT 개념과 연결
- 진단명 정규화 → 다양한 표현을 단일 개념으로 통합
- 처방 의약품 인식 → 약물 온톨로지(RxNorm)와 연결
- 시간 정보 추출 → 질병의 발병, 경과, 치료 타임라인 구성

이를 통해 수백만 건의 비구조화 임상 기록에서 환자 코호트 연구, 임상 품질 지표 측정, 의료 AI 학습 데이터 구축이 가능해집니다.

## 온톨로지가 NLP 모호성을 해소하는 방법

### 어휘 모호성(Lexical Ambiguity) 해소

같은 단어가 여러 의미를 갖는 경우(동음이의어)를 처리합니다.

예시: "배가 고프다" vs. "배를 타다" vs. "배를 먹다"

온톨로지 기반 문맥 분석:
- "배가 고프다" → 맥락: 신체 감각 → 복부(腹)
- "배를 타다" → 맥락: 교통, 이동 → 선박(船)
- "배를 먹다" → 맥락: 음식, 섭취 → 과일(梨)

온톨로지의 개념 계층과 속성 정의를 활용하면 문맥에 맞는 의미를 선택(Word Sense Disambiguation)할 수 있습니다.

### 지시 모호성(Referential Ambiguity) 해소

"그", "그녀", "이것", "저것" 등의 지시어가 무엇을 가리키는지 파악합니다.

예시:
"이순신 장군은 거북선을 이용했다. 그것은 세계 최초의 철갑선이었다."
→ "그것" = 거북선 (지식 그래프에서 이순신-거북선 관계 활용)

> **왜 필요한가? - 한국어 NLP와 온톨로지 통합의 특수성**
> 영어 중심으로 개발된 NLP 도구들은 한국어에 그대로 적용하기 어렵습니다. 한국어의 형태소 분석, 조사 처리, 경어법, 형태론적 복잡성은 특별한 처리가 필요합니다. 한국어 NLP와 온톨로지 통합 기술을 이해하는 것은 한국어 기반 서비스를 개발할 때 필수적입니다.

> **연결 포인트:** NLP의 의미 분석 단계와 5회차에서 배울 Graph RAG는 직접 연결됩니다. NER과 Entity Linking이 사용자 질문에서 엔티티를 추출하면, Graph RAG가 그 엔티티를 기반으로 지식 그래프에서 서브그래프를 검색합니다. 이 두 기술의 품질이 Graph RAG 시스템 전체의 성능을 결정합니다.

## 흔한 오해

### 오해 1: "LLM이 NLP를 대체했으니 온톨로지 NLP는 불필요하다"

대형 언어 모델(LLM)의 등장으로 많은 NLP 작업이 크게 향상되었습니다. 그러나 LLM은 다음과 같은 한계가 있습니다:
- 의료, 법률 등 특수 도메인에서 정확성 부족
- 추론 과정이 불투명하여 설명 불가능
- 훈련 데이터 이후의 최신 정보 반영 불가
- 환각(Hallucination) 문제

온톨로지 기반 NLP는 이런 한계를 보완합니다. 실제로 최신 NLP 시스템은 LLM과 온톨로지를 결합하는 방향으로 발전하고 있습니다.

### 오해 2: "NER은 간단한 기술이다"

개체명 인식이 언뜻 보면 단순해 보이지만, 실제로는 매우 도전적인 기술입니다. "삼성"이 "삼성전자"인지, "삼성물산"인지, "삼성병원"인지를 구분하는 것, "1월 1일"이 날짜인지 조직명의 일부인지 판단하는 것, 도메인 특화 약어와 신조어를 처리하는 것 모두 쉽지 않습니다.

### 오해 3: "온톨로지 없이도 NLP로 지식을 추출할 수 있다"

온톨로지 없이 NLP로 텍스트에서 정보를 추출하는 것은 가능합니다. 그러나 그 결과를 구조화하고, 다른 지식과 연결하고, 일관성 있게 관리하려면 온톨로지가 필수적입니다. 온톨로지는 추출된 지식의 "집"(Home)을 제공합니다.

## 요약

이번 세션에서 우리는 다음을 학습했습니다:

1. **NLP 파이프라인**: 토큰화, 품사 태깅, NER, 구문 분석, 의미 분석의 단계를 거쳐 텍스트에서 구조화된 정보를 추출합니다.

2. **NER과 Entity Linking**: 텍스트의 언급을 온톨로지의 엔티티와 연결함으로써 비구조화 텍스트를 지식 그래프에 통합합니다.

3. **관계 추출**: 패턴 기반, 기계학습 기반, 원격 감독 등의 방법으로 엔티티 간 관계를 자동 추출합니다.

4. **모호성 해소**: 온톨로지는 어휘 모호성과 지시 모호성 해소에 도움을 줍니다.

5. **WordNet과 온톨로지**: 언어적 의미 관계(WordNet)와 도메인 지식(온톨로지)을 결합하면 더 강력한 NLP 시스템을 구축할 수 있습니다.
