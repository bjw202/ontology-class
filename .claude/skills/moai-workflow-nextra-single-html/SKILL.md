# Nextra Single HTML Export

Converts a Next.js 15 + Nextra 4.x documentation site into one portable, self-contained HTML file with working Mermaid diagrams, inline CSS, and hash-based navigation.

---

## Quick Reference (30 seconds)

**What it does:** Runs `next build` in static export mode, then bundles all generated HTML pages, real Nextra/Tailwind CSS, and Mermaid diagrams into a single `.html` file.

**When to use:**
- Distributing docs offline (email, USB, intranet)
- Archiving a snapshot of versioned documentation
- Sharing a complete docs site without hosting infrastructure

**Prerequisites:**
- Next.js 15+ with Nextra 4.x
- Content authored in MDX files
- Mermaid diagrams via `<MermaidDiagram chart={`...`}>` component (optional)
- Node.js 18+

**Output:** `ontology-single.html` (or a project-named equivalent) — one file, no external dependencies except the Mermaid CDN script tag.

---

## Core Problem & Solution

### Why Mermaid Diagrams Break in Static Export

`MermaidDiagram` is a `'use client'` React component that uses `useEffect` to initialize Mermaid.js. In a standard `next build --export`, only the initial render state is written to HTML. Since `useEffect` never runs server-side, the initial state is the loading placeholder ("다이어그램 로딩 중..." or similar).

When the single HTML file is opened in a browser, there is no React runtime to hydrate the components, so Mermaid never initializes and users see only the loading text.

### Solution: MDX Source Parsing + Mermaid CDN Injection

Instead of relying on React hydration, the bundler script:

1. Reads every `.mdx` source file in the `content/` directory
2. Extracts the raw Mermaid chart strings using a regex on `<MermaidDiagram chart={`...`}>` tags
3. Replaces the loading placeholder `<div>` elements in the generated HTML with `<pre class="mermaid">` blocks containing the extracted chart source
4. Injects the Mermaid CDN `<script>` at the bottom of the final HTML with an `initialize` call

This approach is order-dependent: the Nth loading div in the rendered HTML corresponds to the Nth `<MermaidDiagram>` call in the MDX source, matching them positionally.

## Implementation Guide

### Step 1: Configure next.config.mjs

Add conditional static export only when the `NEXT_STATIC_EXPORT` environment variable is set. This avoids breaking the normal dev and production build modes.

```js
// next.config.mjs
const isStaticExport = process.env.NEXT_STATIC_EXPORT === '1';

const nextConfig = {
  // ... existing config
  ...(isStaticExport && {
    output: 'export',
    images: { unoptimized: true },
  }),
};

export default nextConfig;
```

The `images: { unoptimized: true }` is required because Next.js Image Optimization is not available in static export mode.

### Step 2: Create scripts/static-export-bundle.js

Create this Node.js script (no external dependencies beyond Node.js built-ins). The script must implement the following functions:

**`readNextCSS(outDir)`**
- Glob `out/_next/static/css/*.css`
- Concatenate all CSS files into one string
- This captures the real Nextra + Tailwind CSS generated by the build

**`extractArticleContent(html)`**
- Parse the Next.js generated HTML string
- Extract the inner HTML of the first `<article>` element
- Falls back to `<main>` if no `<article>` is found
- Returns empty string with a warning if neither is found

**`extractMermaidCharts(mdxContent)`**
- Apply this multiline regex to the MDX source:
  ```
  /<MermaidDiagram[\s\S]*?chart=\{`([\s\S]*?)`\}[\s\S]*?\/>/g
  ```
- Collect each capture group (the raw chart definition string) into an array
- Return the array in document order

**`replaceMermaidPlaceholders(html, charts)`**
- Find loading placeholder divs in the HTML using a pattern like:
  ```
  /<div[^>]*>다이어그램 로딩 중\.\.\.<\/div>/g
  ```
  (adjust the loading text to match your actual component output)
- Replace each match positionally with:
  ```html
  <pre class="mermaid">CHART_SOURCE_HERE</pre>
  ```
- Log a warning if the count of placeholders does not match the count of charts

**`buildNavigation(pages)`**
- Accept an array of page objects with `{ id, title, path }`
- Generate an HTML sidebar `<nav>` with anchor links using `href="#page-id"` format
- Group pages by top-level section if structure permits

**Final HTML assembly:**
```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <style>/* inlined CSS from readNextCSS() */</style>
</head>
<body>
  <nav><!-- sidebar from buildNavigation() --></nav>
  <main>
    <section id="page-id-1"><!-- article content --></section>
    <section id="page-id-2"><!-- article content --></section>
    <!-- ... -->
  </main>
  <script src="https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js"></script>
  <script>
    mermaid.initialize({ startOnLoad: true, theme: 'default' });

    // Hash-based navigation
    function showSection(hash) {
      document.querySelectorAll('main > section').forEach(s => {
        s.style.display = (s.id === hash.replace('#', '')) ? 'block' : 'none';
      });
    }
    window.addEventListener('hashchange', () => showSection(location.hash));
    if (location.hash) showSection(location.hash);
  </script>
</body>
</html>
```

### Step 3: Add npm scripts to package.json

```json
{
  "scripts": {
    "build:export": "NEXT_STATIC_EXPORT=1 next build",
    "bundle:single": "node scripts/static-export-bundle.js",
    "build:single-full": "npm run build:export && npm run bundle:single"
  }
}
```

### Step 4: Run

```bash
npm run build:single-full
```

Expected output:
- Build runs and generates `out/` directory
- Bundler reads all HTML files from `out/`
- Script prints page count, CSS size, diagram replacement count
- Final file written to project root (e.g., `ontology-single.html`)

Open the file directly in a browser. No server required.

## File Path Mapping

Next.js App Router with Nextra maps MDX content files to output HTML as follows:

| MDX source path | Generated HTML path |
|---|---|
| `content/index.mdx` | `out/index.html` |
| `content/phase-1/index.mdx` | `out/phase-1.html` |
| `content/phase-1/01-motivation.mdx` | `out/phase-1/01-motivation.html` |
| `content/phase-2/02-concepts.mdx` | `out/phase-2/02-concepts.html` |

**Key rule:** An `index.mdx` inside a directory maps to the parent directory's `.html` file (not `directory/index.html`). This differs from plain Next.js App Router behavior because Nextra flattens the index.

When building the page list in the bundler script, read the `out/` directory recursively and map `.html` file paths back to logical section IDs for navigation.

## Mermaid Diagram Handling

### The Critical Regex

```js
const mermaidRegex = /<MermaidDiagram[\s\S]*?chart=\{`([\s\S]*?)`\}[\s\S]*?\/>/g;
```

This matches JSX self-closing tags across multiple lines and captures the template literal content between backticks. The `[\s\S]*?` (non-greedy) is essential for handling multiple diagrams in one file.

Usage in the bundler:

```js
function extractMermaidCharts(mdxContent) {
  const charts = [];
  let match;
  const regex = /<MermaidDiagram[\s\S]*?chart=\{`([\s\S]*?)`\}[\s\S]*?\/>/g;
  while ((match = regex.exec(mdxContent)) !== null) {
    charts.push(match[1].trim());
  }
  return charts;
}
```

### Replacement Strategy

The bundler reads the MDX file for each page and extracts charts in document order. The generated HTML for the same page lists the loading placeholders in the same order (React renders components top-to-bottom). Replace positionally:

```js
let chartIndex = 0;
html = html.replace(/<div[^>]*>다이어그램 로딩 중\.\.\.<\/div>/g, () => {
  if (chartIndex >= charts.length) return '';
  return `<pre class="mermaid">${charts[chartIndex++]}</pre>`;
});
```

If your loading text is different, grep the generated `out/` HTML to find the exact string:

```bash
grep -r "로딩" out/ | head -5
```

## Best Practices

**DO:**
- Run `build:export` before `bundle:single` — the bundler reads from `out/`, which only exists after the export build
- Check your actual loading placeholder text in the generated HTML before writing the replacement regex
- Verify Mermaid CDN availability in your target environment; use a locally vendored copy for fully offline deployment
- Keep `NEXT_STATIC_EXPORT=1` scoped to the export script only — setting it globally breaks normal dev mode

**DO NOT:**
- Do not commit the `out/` directory to version control — it is generated and large
- Do not use `next export` (deprecated) — use `output: 'export'` in `next.config.mjs`
- Do not assume diagram order is alphabetical by file — it follows MDX document order
- Do not hardcode CSS paths — the hash in `_next/static/css/*.css` changes with each build

## Troubleshooting

**"HTML not found" warnings for a page:**
The bundler could not find the `.html` file for a content path. Check the path mapping rules in the File Path Mapping section. An `index.mdx` inside a subdirectory maps to `subdirectory.html`, not `subdirectory/index.html`.

**Mermaid not rendering (blank or "Loading..." text remains):**
- Confirm the CDN script is reachable from the browser
- Open DevTools console and check for Mermaid errors
- Verify the regex captured charts: add `console.log(charts)` to the extraction function
- Confirm the placeholder text in the regex matches what is actually in the generated HTML

**CSS not applied (unstyled output):**
The bundler reads CSS from `out/_next/static/css/`. This directory only exists after a successful `build:export`. Run `npm run build:export` first, then `bundle:single`.

**Nextra version compatibility:**
This workflow is tested with Nextra 4.x and Next.js 15. Nextra 3.x uses a different page router structure and the `<article>` extraction selector may need adjustment. Check the generated HTML structure with:

```bash
grep -n "<article" out/index.html | head -5
```

**Images not appearing:**
Static export with `images: { unoptimized: true }` copies images to `out/` with relative paths. In a single HTML file, relative image paths will break. Either embed images as base64 data URIs in the bundler or host them separately.
